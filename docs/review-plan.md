2. Цели ревью
1. Проверить точность расчета итоговой стоимости товаров, корректность применения скидок и промокодов.
2. Оценить производительность отрисовки компонента (отсутствие лишних ререндеров) и надежность интеграции с бэкенд-API и платежной системой.
3. Критерии проверки (чек-лист)
3.1. Функциональная корректность
- [ ] Итоговая сумма корзины и размер скидки пересчитываются без ошибок округления (с точностью до копеек) при изменении количества товаров.
- [ ] Корректно обрабатываются граничные состояния: пустая корзина, удаление последнего товара, ввод недействительного промокода.
3.2. Безопасность / Надежность
- [ ] Чувствительные платежные данные не сохраняются в localStorage или sessionStorage, а передаются только по защищенному протоколу (HTTPS).
- [ ] Ошибки сетевых запросов к бэкенд-API и платежному шлюзу перехватываются и отображают понятное уведомление для пользователя без падения интерфейса.
3.3. Производительность
- [ ] Время первичной отрисовки (рендеринга) компонента при наличии до 50 товаров в корзине не превышает 100 мс.
- [ ] Для тяжелых вычислений и дочерних элементов списка используются механизмы мемоизации (useMemo, React.memo) для предотвращения лишних перерисовок.
3.4. Читаемость и стиль
- [ ] Код строго типизирован на TypeScript (отсутствует использование типа any для пропсов, состояний и ответов API).
